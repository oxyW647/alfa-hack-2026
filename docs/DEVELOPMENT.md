# Разработка и локальный запуск

**Проект:** «Умный кредитный кабинет предпринимателя» · Альфа-Хак 2026
**Назначение:** технические инструкции для команды. Обзор продукта и демонстрация для жюри находятся в [основном README](../README.md).

## 1. Состав проекта

| Путь от корня репозитория | Назначение |
|---|---|
| `backend/` | FastAPI, SQLAlchemy (async), PostgreSQL, Alembic, пакетный менеджер `uv` |
| `frontend/` | React, TypeScript, Vite, Tailwind CSS; кабинеты клиента и сотрудника |
| `nginx/` | Раздача frontend и проксирование `/api` на backend |
| `docs/` | Архитектура, API, тестовые сценарии, исходные материалы модели |

Экспертный алгоритм из `docs/alfa/scoring.py` (версия `1.2.0`) перенесён в `backend/app/services/scoring.py` без изменения весов и формул. Он сверялся с 1 500 синтетическими валидными и 34 ошибочными запросами. **Эти данные проверяют реализацию формул, но не точность прогнозирования кредитных дефолтов.**

Актуальные правила перехода между этапами находятся в `backend/app/services/routing.py`, конфигурация продукта и пороги — в `backend/app/core/policy.py`. Старый `docs/alfa/credit_policy.py` — исторический материал, его нельзя подключать как вторую независимую кредитную политику.

## 2. Требования

- Для всего приложения: Docker Desktop или Docker Engine с Docker Compose.
- Для работы без Docker: Python 3.12, `uv`, Node.js 20+ и npm.

## 3. Запуск приложения через Docker

Открой терминал **в корне репозитория**, где находится `docker-compose.yml`.

**Windows PowerShell (первый запуск):**

```powershell
Copy-Item .env.example .env
# Проверь настройки в .env
docker compose up --build
```

**Linux/macOS (первый запуск):**

```bash
cp .env.example .env
docker compose up --build
```

Если `.env` уже существует, повторно копировать шаблон не нужно. Файл `.env` — локальная конфигурация, **не добавляй его в Git**. Файл `.env.example` остаётся в репозитории.

Адреса при стандартном `HTTP_PORT=8080`:

- Приложение: <http://localhost:8080>
- Swagger UI: <http://localhost:8080/api/docs>
- OpenAPI: <http://localhost:8080/api/openapi.json>

Проверка контейнеров в другом терминале:

```powershell
docker compose ps
```

Остановка приложения (с сохранением данных PostgreSQL в Docker volume):

```powershell
docker compose down
```

В Compose используются `db` (`postgres:16-alpine`), `backend` (миграции Alembic и Gunicorn), `frontend` (одноразовая сборка Vite) и `nginx` (порт приложения). Контейнер сборки frontend может завершиться со статусом `Exited (0)` — это нормальное поведение одноразового сервиса, если остальной стек запустился.

### Демо-аккаунты

При запуске создаются демо-пользователи с учётными данными из `.env`. В прототипе frontend автоматически входит под демо-пользователем и позволяет переключать роли в шапке. Для Swagger авторизация доступна по `POST /api/v1/auth/login`.

| Роль | E-mail по умолчанию | Пароль по умолчанию |
|---|---|---|
| Клиент | `client@credit-demo.ru` | `client-demo-pass` |
| Сотрудник | `employee@credit-demo.ru` | `employee-demo-pass` |

Эти логины/пароли подходят **только для локальной демонстрации**; они не предназначены для публичного развёртывания. Демо-учётные данные попадают в frontend-сборку.

## 4. Кредитный конвейер и сценарии проверки

Процесс состоит из пяти этапов: **предварительный скоринг → документы → проверка → итоговый скоринг → финальное решение**. Баллы рассчитывает сервер; клиент видит только статус и доступные действия, а сотрудник — внутренние метрики.

**Предварительная маршрутизация** (до документов):

| Балл | Маршрут | Автоматический переход к документам |
|---|---|---|
| 0–45 | `DECLINED` | Нет: отказ |
| 46–75 | `MANUAL_REVIEW` | Нет: ожидание сотрудника |
| 76–100 | `REQUEST_DOCUMENTS` | Да |

Сотрудник может разрешить проверку документов для предварительного `MANUAL_REVIEW`. Такой допуск **не означает одобрения кредита**. После документов выполняется повторная оценка и отдельное финальное решение. Техническая ошибка этапа (`FAILED`) не равна кредитному отказу.

**Финальная политика:** действующая серьёзная просрочка, неположительный капитал, недоверенные документы, неуспешный/неподтверждённый антифрод либо отсутствие подтверждения кредитной истории исключают автоодобрение. Прекращение регистрации или недоступность продукта ведут к отказу. Эти ограничения — демонстрационные правила команды.

**Альтернативные предложения** перебираются только при допустимых подтверждённых данных и проверках: для каждого изменения суммы/срока повторно вызываются скоринг и кредитные правила. Если подходящих условий нет, предложение не формируется. **После ручного отказа сотрудника ранее рассчитанная альтернатива отменяется** — нельзя обещать клиенту предложение после такого отказа.

### Основной демонстрационный сценарий

1. В роли клиента выбери «Новая заявка» → сценарий кофейни (`cafe`) → создай заявку.
2. Нажми «Запустить всё». Предварительная оценка — **92**, поэтому конвейер допускает проверку документов.
3. После документов оценка меняется на **62**, маршрут — `MANUAL_REVIEW`. В кабинете сотрудника доступны расхождения данных и объяснение баллов.
4. Сотрудник принимает **финальное** ручное решение. При одобрении клиент может принять демонстрационное предложение; при отказе заявка получает статус «Заявка не одобрена», ранее рассчитанная альтернатива недоступна.

**Сценарий среднего предварительного балла:** `medium_risk` получает **75** при предварительной оценке → этапы блокируются → сотрудник может допустить к документам → после проверки оценка **65**, и требуется уже отдельное финальное решение сотрудника.

Прочие кейсы, контроль доступа, пороги 45/46 и 75/76, ошибки ввода и стоп-факторы описаны в [TEST_SCENARIOS.md](TEST_SCENARIOS.md).

## 5. Локальная разработка без полного Docker-стека

Из **корня репозитория** запусти базу данных:

```powershell
docker compose up -d db
```

Перейди в `backend/` и установи зависимости:

```powershell
cd backend
uv sync --frozen
```

В `.env.example` адрес базы `db` предназначен для сети Docker; для локального backend используй `localhost`.

**PowerShell:**

```powershell
$env:DATABASE_URL = "postgresql+asyncpg://credit:credit-demo-password@localhost:5432/credit_cabinet"
$env:MOCK_DOCS_DIR = "mock_docs"
uv run alembic upgrade head
uv run uvicorn app.main:app --reload --port 8000
```

**Bash (Linux/macOS):**

```bash
export DATABASE_URL=postgresql+asyncpg://credit:credit-demo-password@localhost:5432/credit_cabinet
export MOCK_DOCS_DIR=mock_docs
uv run alembic upgrade head
uv run uvicorn app.main:app --reload --port 8000
```

Указанные параметры подключения соответствуют **шаблонной демо-конфигурации**. Если менялись пароль или `POSTGRES_PORT` в `.env`, измени и локальную строку подключения. PowerShell-переменные действуют в текущей сессии.

Во втором терминале из **корня репозитория**:

```powershell
cd frontend
npm ci
npm run dev
```

## 6. Проверки качества

**Backend** (находясь в `backend/`):

```powershell
uv sync --frozen
uv run --with pytest python -m pytest -q
uv run ruff check .
```

**Frontend** (из корня репозитория):

```powershell
cd frontend
npm ci
npm run lint
npm run build
```

Успешный `docker compose up --build` доказывает, что стек собрался и запустился; **это не заменяет** проверку маршрутов, ролевых прав и действий сотрудника. Перед PR необходимо запустить тесты и пройти контрольные UI-сценарии из [TEST_SCENARIOS.md](TEST_SCENARIOS.md).

## 7. Переменные окружения

Настройки лежат в `.env` в корне репозитория. Копируй `.env.example` и не публикуй реальные секреты.

| Переменная | Назначение |
|---|---|
| `HTTP_PORT` | Порт Nginx на хосте (в Compose по умолчанию 8080) |
| `POSTGRES_USER`, `POSTGRES_PASSWORD`, `POSTGRES_DB`, `POSTGRES_PORT` | Параметры PostgreSQL в Docker |
| `GUNICORN_WORKERS` | Количество процессов backend |
| `APP_NAME`, `DATABASE_URL` | Название приложения и адрес БД для backend |
| `JWT_SECRET`, `JWT_ALGORITHM`, `ACCESS_TOKEN_TTL_MINUTES` | Параметры токенов JWT |
| `MOCK_DOCS_DIR` | Путь к локальным JSON-мокам |
| `DEMO_CLIENT_EMAIL`, `DEMO_CLIENT_PASSWORD`, `DEMO_EMPLOYEE_EMAIL`, `DEMO_EMPLOYEE_PASSWORD` | Демо-аккаунты |

В `backend/app/core/config.py` нет значений по умолчанию для полей `Settings`; в то же время часть параметров инфраструктуры (например, `HTTP_PORT` и `POSTGRES_PORT`) обслуживается Docker Compose и может иметь значение по умолчанию. Не следует путать эти уровни конфигурации.
