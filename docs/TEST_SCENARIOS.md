# Тестовые сценарии

Во всех сценариях используются демо-аккаунты из [README](../README.md) и готовые наборы данных
из списка «Сценарий» на форме новой заявки (`GET /demo/scenarios`). Числа ниже — реальный
результат работы стека. Роль переключается кнопками в шапке.

## Сквозные сценарии

| № | Сценарий | Действия | Ожидаемый результат |
|---|---|---|---|
| 1 | Одобрение (`low_risk`, ИНН 7701234561, 1 000 000 ₽ на 12 мес.) | Создать заявку, «Запустить всё», открыть заявку | Предварительная и итоговая оценка 100, маршрут `APPROVED`. Клиент: «Одобрено (демо)» с условиями, платёж 94 559,60 ₽. Принять предложение → «Предложение принято»; повторное принятие → `409` |
| 2 | Падение оценки после документов (`cafe`, ИНН 781045678123, 1 200 000 ₽ на 24 мес.) | Создать заявку, «Запустить всё», открыть под сотрудником | Предварительная оценка 92 и `REQUEST_DOCUMENTS`, итоговая 62 и `MANUAL_REVIEW`, дельта −30. В проверках предупреждение «Анкета и документы»: расхождения по долгу, капиталу, активам и обязательствам |
| 3 | Ручное одобрение (`medium_risk`, ИНН 8579875343, 1 500 000 ₽ на 12 мес.) | «Запустить всё»; клиент видит «На рассмотрении»; сотрудник нажимает «Одобрить» | Предварительная 75, итоговая 65, маршрут `MANUAL_REVIEW`. После решения клиент видит «Одобрено (демо)» с запрошенными условиями |
| 4 | Ручной отказ и альтернатива (`medium_risk`) | Сотрудник нажимает «Отклонить» | Клиент: «Не одобрено (демо)» и альтернативное предложение 1 400 000 ₽ на 18 мес., платёж 93 382,94 ₽. Принять альтернативу → «Предложение принято», в заявке `accepted_offer.kind = alternative` |
| 5 | Отказ по регистрации (`high_risk`, ИНН 3405120002) | «Запустить всё» | Оценки 48 и 40, маршрут `DECLINED`, проверка «Регистрация действует» не пройдена, альтернативного предложения нет |
| 6 | Неизвестная компания, документы от клиента | Создать заявку из `low_risk` с ИНН `5000000000`, «Запустить всё»; клиентом загрузить три документа (панель «Документы»), снова «Запустить всё» | Сначала этап «Получение документов» с ошибкой, статус «Нужны уточнения», три действия `UPLOAD_DOCUMENT`. После загрузки оценка 100, но маршрут `MANUAL_REVIEW` («На рассмотрении»): документы клиента недоверенные, проверка «Источник документов» — предупреждение, предложения нет |
| 6а | То же, документы от сотрудника | Те же три документа загрузить под сотрудником, запустить конвейер | Источник `employee`, документы доверенные, маршрут `APPROVED`, клиент: «Одобрено (демо)» |
| 7 | Неполная анкета | Создать заявку, в JSON анкеты оставить только `{"age_months": 24}`, запустить | Предварительная оценка с ошибкой `INSUFFICIENT_DATA`, поле `financials.revenues_last_6_months_rub`; клиент видит действие «Заполнить» этого поля. После правки анкеты кнопкой «Анкета» запуск проходит |
| 8 | Порядок этапов | Нажать «Запустить» на этапе «Проверка данных» до предыдущих | Этап недоступен (`locked`); прямой вызов API — `409 «Сначала выполните этап …»` |
| 9 | Сброс при правке | Выполнить конвейер, изменить сумму в «Анкета» | Статус `DRAFT`, этапы сброшены, прежние оценки сохраняются в истории оценок сотрудника |

## Права доступа

| Проверка | Ожидаемый результат |
|---|---|
| Запрос к API без токена | `401 «Требуется авторизация»` |
| Неверный пароль | `401 «Неверный e-mail или пароль»` |
| Клиент вызывает `manual-review` | `403 «Недостаточно прав»` |
| Клиент запрашивает конвейер | `result` у всех этапов `null`, в заявке нет оценок и проверок |
| Клиент загружает документ поверх документа из реестра | `409 «Документ получен из реестра и не может быть заменён»`, документ не меняется |
| Ручное решение по заявке не в `MANUAL_REVIEW` | `409 «Заявка не ожидает ручного решения»` |

## Валидация

| Проверка | Ожидаемый результат |
|---|---|
| ИНН не из 10 или 12 цифр | `422`, `field = company.inn`, русский текст |
| Сумма вне границ продукта (меньше 300 000 или больше 25 000 000 ₽) | Заявка создаётся, проверка «Соответствие продукту» не пройдена, маршрут `DECLINED` |
| Загрузка документа с неверной структурой | `422` с путём поля |

## Эталон для скоринга

Расчёт модели можно сверить с полем `expected` каждого кейса в
`docs/alfa/synthetic_borrowers.json` (1500 валидных кейсов) и `docs/alfa/invalid_cases.json`
(34 ошибочных, ожидаемые `code` и `field`). При переносе в `backend/app/services/scoring.py`
результат совпал по всем кейсам.
